# perf-contention summary
Toolchain: GOTOOLCHAIN=go1.26.6, darwin/arm64 Apple M4 Max (16 cores), shared with ~15 other agents -> wall-clock
numbers are noisy (serial BenchmarkPCWorkUnit, pure CPU, varied 4.4us..38us across runs). Rates (miss/fail per op)
are the robust signal; ns/op scaling ratios are indicative only.
Commands (run in private copy /tmp/ddiast-review/wt/perf-contention, files copied here):
  go test -run '^$' -bench PC -benchtime=200ms -count=3 -cpu=1,4,8,16 -mutexprofile=store.mutex.pprof -blockprofile=store.block.pprof ./internal/taint/store
  go test -run '^$' -bench PC -benchtime=200ms -count=3 -cpu=1,4,8,16 -mutexprofile=request.mutex.pprof -blockprofile=request.block.pprof ./internal/taint/request
  go test -run '^$' -bench 'PCBeginRequestFinish|PCIntraRequestVisitOnly' -benchtime=200ms -count=3 -cpu=1,2,4,8,16 ./internal/taint/request   (request2)
  go test -run '^$' -bench 'PCRequestLifecycle|PCAcquireFinishSerial|PCFinishSerial|PCWorkUnit' -benchtime=200ms -count=3 -cpu=1,4,8,16 -mutexprofile=store2.mutex.pprof ./internal/taint/store (store2)
  go test -run TestPC -v ./internal/taint/store ./internal/taint/request   (mechanism.test.txt)
Note: store.bench.txt PCRequestLifecycle* rows are from the first version without simulated handler work (failed attempts retried immediately);
store2.bench.txt has the corrected version (pcWork on every op). BenchmarkPCDeriveOwnOwner/MixedReadWrite are in store.bench.txt.
