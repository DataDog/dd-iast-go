# part-perf: Performance (hot paths, escape, contention, complexity, memory, build cost, GC, disabled mode, benchmark quality)

**Counts after dedup by root cause: 1 Critical, 4 High, 15 Medium.** All Critical and High entries cite their phase-3 `fx-*` verdict file(s); the phase-3 adjusted severity is authoritative for them.

## Part verdict

No perf-scope defect crashes, deadlocks, or corrupts the host application, and per-request memory is hard-bounded and fully released (all IAST gauges return to zero; worst-case live heap tracks the 2 MiB request budget; one-time 14.25 MB init) — verified by perf-memory and perf-gc. Crash-safety of the hot path holds: every propagation/lookup lock is a try-lock with consistent lock order, so no blocking and no deadlock cycle (perf-contention). Provenance is not directly wronged by perf code, but contention try-locks cause silent false negatives on the read path (M3) and observably reduce the effective sampling rate via admission try-lock drops that phase 3 classified as a documented design allowance. The real problem is product rule 2 ("never slow the host more than strictly necessary"): four confirmed defects make customer code pay large, avoidable, discarded work — full report work before every gate (H1), writer scans on clean values (H2), unconditional heap allocations from non-inlinable woven wrappers even with IAST disabled (H3), per-range source rehashing (H4) — plus the Critical Go 1.27 build-time failure (C1). Benchmark methodology is sound but structurally blind to the tainted-hit path (M13).

## Findings by root cause

### C1. Woven Go 1.27 builds: encoding/json compile break inflates the Orchestrion job-server to 22–24 GB and aborts the build
- **Severity:** Critical (phase-3 adjusted: Critical)
- **Status:** CONFIRMED — `phase3/fx-base-test-127-F1.json` (entries `base-test-127-F1`, `hooks-compile-matrix-F2`, `hooks-compile-matrix-F6`; the falsifier states the two compile-break reports duplicate one defect and the memory explosion is its amplification)
- **Location:** iast/encoding/json/orchestrion.yml:28-47 (woven Decoder references `dec.r`/`dec.d`, absent from Go 1.27's json-v2 `v2_stream.go`); amplification in orchestrion@23afa71 `internal/jobserver/nbt/nbt.go:161-162,252-253`
- **Contributing ids:** base-test-127-F1, hooks-compile-matrix-F2, hooks-compile-matrix-F6 (cross-part: phase-1 base + hooks; primary home of the compile break is part-hooks, the build-cost/memory amplification is perf-scope)
- **Mechanism:** On Go 1.27 the json weave injects `dec.r`/`dec.d` references absent from the v2 Decoder (`v2_stream.go`), so woven `encoding/json` — and any package reaching it through dd-iast-go's dependency closure — fails to compile. The failing build then drives the Orchestrion job-server from 1.6 GiB to 17–22 GiB in ~20–50 s and aborts with `nats: maximum payload exceeded`; the falsifier independently reproduced **24,120,426,496 B peak RSS** on a one-file JSON-free program (nojsonv2 control: 426 MB, success). This is the likely source of the ~40 GB orchestrion process in the brief. Go 1.26.6 woven builds stayed ≤ 1.33 GiB.
- **Reproduction:** `.omo/review/evidence/fx-base-test-127-F1/` (`build127-default.txt`, `json127-compiler.txt`); from a private copy: `GOTOOLCHAIN=local GOFLAGS=-p=4 /usr/bin/time -l timeout 180 go tool orchestrion go build -o /dev/null ./repro` → exit 1, max RSS 24.1 GB. Original matrix: `.omo/review/evidence/hooks-compile-matrix/`.
- **Minimal fix:** Gate the Decoder weave on Go 1.26 / json-v1 (build tags or a toolchain-version check in the aspect) — the nojsonv2 control proves the rest of the weave set is fine on 1.27 — and bound error retention in the orchestrion job-server (upstream).

### H1. The vulnerability report path runs all expensive work (orphan span, UUID, depth-32 stack capture, evidence, redaction, model build) before the sampling/quota/dedup gates
- **Severity:** High (phase-3 adjusted: High for every contributing finding)
- **Status:** CONFIRMED — `phase3/fx-perf-memory-F1.json`, `phase3/fx-crash-hostile-input-F2.json`, `phase3/fx-life-spans-F4.json` (this file is a three-entry verdict covering `life-spans-F4`, `sink-vuln-report-F1`, **and** `perf-allocs-matrix-F1`, all CONFIRMED High as one root cause)
- **Location:** internal/vulnerability/report.go:44-105; internal/vulnerability/tainted.go:57-93 (only dedup test, `dedup.Set.Check`, at :93); internal/spans/vulnerability.go:17-19; iast/database/sql/sql.go:34-49
- **Contributing ids:** perf-allocs-matrix-F1, perf-allocs-matrix-F3, perf-memory-F1, crash-hostile-input-F2, life-spans-F4, sink-vuln-report-F1, sink-vuln-report-F7, sink-vuln-report-F8 (cross-part: crash-hostile-input, life-spans, sink-vuln-report)
- **Mechanism:** `Report`/`ReportTainted` start and finish a real orphan tracer span before any sampling decision, generate a UUID, capture a depth-32 dd-trace stack trace, run `evidence.CollectString`, `redaction.AnalyzeSQL` (up to 6 dialect lexings of 32 KiB), `BuildWithSensitive`, and build the `model.Vulnerability` — and only then take the annotation lock and test `CanAddVulnerability` (quota, default 2/request) or the event-local hash; the SQLi hash covers only type+location, so no evidence or redaction is needed for the decision, and the crypto `Report` path has no process dedup at all. This is the production steady state: the same call sites are re-hit every sampled request with everything discarded — ~11.7–17.9 KB/request for deduplicated SQLi (falsifier: 3.65 MB over 320 requests, 1 committed); 28 allocs / 6.8–9.4 µs per `md5.Sum` with 1000 calls publishing 1–2 findings; 100 orphan spans with 0 payloads at sampling=0; ~24x (142 ms vs 5.9 ms) for 40 tainted 30 KB queries at the default quota.
- **Reproduction:** `.omo/review/evidence/perf-memory/` (`summary.txt`, `prof/s100-typical-report-focus.txt`), `.omo/review/evidence/perf-allocs-matrix/repro/` (`zz_repro_weakhash_test.go`, `repro-weakhash.woven-sampling100.txt`: 6767 ns/op, 9825 B/op, 28 allocs vs 119 ns/0 plain), `.omo/review/evidence/fx-perf-memory-F1/`, `.omo/review/evidence/fx-life-spans-F4/`, `.omo/review/evidence/fx-crash-hostile-input-F2/` (exact commands in each fx file).
- **Minimal fix:** Compute the hash from type+location (and the shallow first-application-frame) first, early-return via a `WouldDrop(hash)` read under `RLock` when the event is full or already holds the hash, materialize the orphan span only after the sampling decision, capture the full stack only on commit, and add process-level dedup to the crypto `Report` path.

### H2. Writer advice runs the full writer machinery for clean values whenever any request is active: 64-owner scans per Builder/Buffer operation
- **Severity:** High (phase-3 adjusted: High)
- **Status:** CONFIRMED — `phase3/fx-perf-hotpath-F2.json`, `phase3/fx-crash-stress-app-F2.json`
- **Location:** iast/propagation/writer.go:29-35,104-129; internal/taint/propagation/writer.go:21-25 (`WriterActive` = "any sampled request in process"); internal/taint/store/writer.go:75-113,366-432; weave gate iast/propagation/orchestrion.yml:1553-1595
- **Contributing ids:** perf-hotpath-F2, crash-stress-app-F2 (cross-part: crash-stress-app)
- **Mechanism:** `WriterActive()` tests whether *any analysis exists*, not whether a value or writer state exists. With one active but wholly untainted owner, every woven `Builder`/`Buffer` operation (including Reset/String/WriteByte/WriteRune/Grow) gathers before/after views, zeroes a 6312-byte `Snapshot`, and calls `LookupWriterValue`, which walks all 64 owner records; Buffer calls it at least twice, and once any request holds writer state the same applies process-wide (tracer, dependencies, request-less goroutines: ~1,700 atomics at 64 owners; `json.Marshal` x9–x78). Woven customer code: ~16.3 µs vs ~0.31 µs unwoven (~50x). Falsifier confirmed default-config medians (6→475 ns with one tracked owner; 5→1838 ns at 64 owners) with clean no-writer and post-finish controls. Provenance is preserved by the existing `HasWriterStates`/`MayContain` gates, so the scan is pure waste.
- **Reproduction:** `.omo/review/evidence/perf-hotpath/` (`hotpath_review_test.go`, `bench.txt`) and `.omo/review/evidence/fx-perf-hotpath-F2/` (`bench-woven.txt`); stress evidence `.omo/review/evidence/fx-crash-stress-app-F2/`.
- **Minimal fix:** Before gathering views, return the native writer operation when both the process value counter and the writer-state counter are zero; for an owner with unrelated taint, combine a possible-hit check with a tracked-writer-state check to skip the 64-slot scan when both are false.

### H3. Non-inlinable generic advice wrappers make woven []byte→string conversions (and 8–16-operand concats) heap-allocate unconditionally, even with IAST disabled
- **Severity:** High (phase-3 adjusted: High)
- **Status:** CONFIRMED — `phase3/fx-perf-escape-F1.json`, `phase3/fx-hooks-yml-operators-F4.json` (the fx-perf-escape-F1.json file exists and carries a full CONFIRMED/High verdict; a note claiming it was never produced is contradicted by the artifact)
- **Location:** iast/propagation/operators.go:197-204 (`BytesToString` inline cost 131 vs budget 80), :90-196 (Concat8–16 cost 81–97); iast/propagation/orchestrion.yml:327-341
- **Contributing ids:** perf-escape-F1, perf-escape-F4, hooks-yml-operators-F4, hooks-fidelity-strings-F3, prop-concat-conv-json-F1 (cross-part: hooks-yml-operators, hooks-fidelity, prop-concat-conv-json)
- **Mechanism:** The generic wrapper is never inlined into customer packages, so its `result := string(value)` escapes before the `HasValues()` gate can run; plain Go keeps a non-escaping conversion on a 32-byte stack buffer. Every woven `s := string(b)` (assignment, declaration, return, map key, `len(a+b)`, comparison operand) gains +1 heap allocation per execution — with `DD_IAST_ENABLED=false`, `DD_IAST_REQUEST_SAMPLING=0`, outside requests, and on go1.26.6 and go1.27.0. Both falsifiers independently measured 1 alloc vs 0 plain for short local conversions. README:31's "allocation-preserving" claim is false for non-escaping results; the finding contradicts the documented disabled-path allocation-parity requirement.
- **Reproduction:** `.omo/review/evidence/perf-escape/` (`bench-plain.txt` vs `bench-woven.txt`: `ConvLocal` 0→1 alloc; `prototype-fix-v3.patch` restores 0 with woven tests green) and `.omo/review/evidence/fx-perf-escape-F1/`, `.omo/review/evidence/fx-hooks-yml-operators-F4/`.
- **Minimal fix:** Emit a non-generic inlinable gate (`BytesToStringValue`: `if !operatorbridge.HasValues() { return string(v) }` + `//go:noinline` slow path; prototype v3 verified). For Concat8–16, pass a caller-side temporary through a non-generic helper or cap wrapped arity; add woven `AllocsPerRun` regression tests (see also M8/M9/M10).

### H4. The evidence collector rehashes the entire source for every reported range
- **Severity:** High (phase-3 adjusted: High)
- **Status:** CONFIRMED — `phase3/fx-perf-algorithmic-F1.json`
- **Location:** internal/taint/evidence/evidence.go:209-240,277-291
- **Contributing ids:** perf-algorithmic-F1
- **Mechanism:** `collector.addAt` calls `sourceIndex` for every unsafe range; `sourceIndex` hashes the *entire* source name and value before testing whether the source is already indexed. A single HTTP value of length S contributing R disjoint ranges costs O(R·S) at every eligible sink invocation, with S attacker-influenced up to the 64 KiB source-root bound and R up to 64 (default 10). Falsifier: one source + 10 ranges = 10–19x paired collection time, 47.78% of CPU samples in `sourceHash`; the original finder measured 462 µs → 29.1 ms for 8→64 ranges over 4–32 KiB sources.
- **Reproduction:** `.omo/review/evidence/perf-algorithmic/` (`review_scaling_test.go`, `scaling-output.txt`) and `.omo/review/evidence/fx-perf-algorithmic-F1/` (`command-source-output.txt`, `review_command_source_test.go`; command in the fx file).
- **Minimal fix:** Cache source resolution within one collection using a stable owner-local source identifier carried by `ResolvedRange`, keeping exact identity comparison and the fixed source/byte limits.

## What was verified correct

- Allocation neutrality of taint propagation: all 56 benchmark rows across 5 modules have identical allocs/op and B/op plain vs woven; untainted/inactive paths allocate exactly what uninstrumented Go allocates (perf-allocs-matrix; only crypto-sink rows and HTTPRoundTrip differ).
- The kill switch is clean: `DD_IAST_ENABLED=false` restores control allocation counts exactly and takes no permit/owner/scope (perf-allocs-matrix, perf-disabled, perf-memory: +173–228 B weaving-only).
- Disabled/sampled-out propagation gates are allocation-free (named windows, operators, writer state, `FmtSprintf`, `SplitSeq` all match native) (perf-disabled).
- No blocking lock on any propagation or lookup hot path; lock order consistent; no deadlock; readers alone never lose data; `sourceMu` is per-request-slot (perf-contention).
- Memory bounded and fully released: post-GC heap returns to baseline (17–100 B/request noise, same as plain), every IAST gauge zero after Finish, worst case enforces 4,096 values / 2 MiB roots / 64 vulns / 25 KB event caps; 14.25 MB one-time init (perf-memory, perf-gc).
- `weak.Make`/`Value` allocation-free; annotation released synchronously by the woven span-finish hook (perf-gc).
- No super-linear trend in writer/Split/Replace/Concat propagation at fixed capacities; SQL analysis rejects >32 KiB; redaction bounded to 1 MiB comparisons (perf-algorithmic).
- All go1.26.6 woven builds succeeded; warm incremental rebuilds fast (6.7–13.8 s); peak build RSS ≤ 1.14 GB on 1.26.6 (perf-binary-compile).
- Benchmark methodology sound: no dead-code elimination artifacts, `b.Loop()` everywhere, package-level sinks, correct differential runner design; `BytesBufferCopies`/`StringLookup` construct genuinely tainted input (perf-bench-quality).

## Coverage gaps

- No trustworthy wall-clock numbers anywhere in this part: the machine was shared (a pure-CPU control varied 9x); every ratio above is allocation-, drop-rate-, or CPU-profile-based. Quiet-machine `-count>=10` reruns needed before quoting latency.
- No woven end-to-end contention campaign (instrumented `net/http` under a load generator); writer/binding/mutation try-lock drop rates unmeasured (perf-contention).
- Go 1.27 woven behavior largely untestable due to the C1 json compile break; PGO builds (which change inline budgets) untested (perf-escape).
- Escape analysis covered `iast/propagation` only; `iast/net/http`, `io`, `bufio`, `encoding/json`, `database/sql`, `os/exec` advice not dumped (perf-escape).
- H1's absolute cost including span commit and event serialization not timed; `-sampling` sweep between 0 and 100 not run (perf-allocs-matrix, perf-algorithmic).
- perf-bench-quality did not execute the full differential `benchmarks/overhead/runner` end-to-end (reviewed by reading only).
- Unexplained residual from perf-memory: in the worst-case run, 200 JSON-decoded strings came out untainted (78/278 tainted) — deferred to parts sink-json-sources/life-json-decoder.
- The `bench/` evidence directory (micro-plain/micro-woven benchstat, overhead-s0/s100) was not re-analyzed by any perf node; treat as supplementary.
