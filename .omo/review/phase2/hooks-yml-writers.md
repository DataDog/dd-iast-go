# hooks-yml-writers: Builder and Buffer join points
Verdict: Writer provenance and host behavior passed focused checks, but Buffer anchors can exceed the stated memory envelope by a large factor.
Scope covered: `iast/propagation/orchestrion.yml` writer call-site and native `bytes.Buffer` advice; `iast/propagation/writer.go`; `iast/internal/propagationtest/writer.go`; `internal/taint/{propagation,store}/writer.go`; `internal/taint/writerbridge/bridge.go`; writer tests; Go 1.26.6 instrumented behavior and Go `bytes.Buffer`/`strings.Builder` implementations.

## Findings
### hooks-yml-writers-F1: Buffer writer anchors retain unbounded caller allocations
- Severity: High
- Category: memory-bound
- Location: iast/propagation/writer.go:213-216; internal/taint/store/writer.go:17-34,217-229
- Claim: A `bytes.Buffer` initialized with a small full-slice view of a much larger caller allocation yields a small `Capacity` charge, while the typed `Anchor` and retained receiver keep the **entire** allocation alive until owner finish. Eight 16 MiB allocations behind 16-byte views remain live across GC while the store charges only 128 bytes. The 24 MiB feature footprint is therefore not a retained-heap bound; the amplification is arbitrary as caller allocations grow. This challenges the documented writer-anchor trade-off because bounded writer *counts* do not bound retained bytes.
- Evidence: `.omo/review/evidence/hooks-yml-writers/review_retention_test.go` and `retention.txt`; from the private copy, `GOTOOLCHAIN=go1.26.6 go test -count=1 -timeout=5m ./internal/taint/store -run TestReviewBufferAnchorsExceedAdvertisedMemoryCeiling -v` fails with `live heap increase=128 MiB, store charged=128 bytes, writer records=8` and `advertised 24 MiB footprint exceeded by retained buffer allocations`.
- Fix: Do not retain strong references to arbitrarily large caller-owned backing/receivers in persistent writer records unless their entire retained allocation can be bounded. Use an identity/lifetime mechanism that does not pin the backing, or conservatively drop writer provenance when no bounded ownership representation is available; retain native Buffer values and results.

## Checked and found correct
- `writer.go:208-216`: for `value := buffer.Bytes()`, `cap(value) = buffer.Cap() - off`, so `Backing = uintptr(Anchor) - off` is the start of `buffer.buf`, even when that slice starts inside a larger allocation. `Backing` remains a **numeric interval key**, never a pointer constructed from `uintptr` or dereferenced; `Anchor` remains a typed pointer to the live allocation. When the unread slice has zero capacity, no backing address is computed. A private-copy test checks interior views across write, compaction, truncation and reset with `-d=checkptr=2`: `.omo/review/evidence/hooks-yml-writers/review_view_test.go` and `view-checkptr.txt`.
- Direct `Builder` wrappers call the native operation once after capturing the prior view; `Builder.String`/`Len`/`Cap` do not call `copyCheck` or modify the builder. A copied nonzero Builder still panics at the native write or Grow. Native `Buffer.String` handles a nil receiver; the wrapper preserves that case and other methods retain their native nil/invalid-argument panics.
- Native `bytes.Buffer` hooks distinguish backing writes, header-only changes and mutable exposure. The bounded expectation marker suppresses the wrapper's internal `Bytes()` observation, while backing writes invalidate overlapping copied receivers. Failed marker admission drops provenance rather than preserving a stale writer. The writer store compares complete views for value-copy adoption and releases typed anchors with owner finish.
- The existing instrumented writer tests passed on Go 1.26.6 with `GOTOOLCHAIN=go1.26.6 go tool orchestrion go test -count=1 -timeout=12m ./iast/propagation -run 'Test(Buffer|Builder|Writer)' -v`, and with `-race -count=1 -timeout=12m` (`ok github.com/DataDog/dd-iast-go/iast/propagation 1.824s`). They cover value copies, partial reads, aliases, overlapping writes, marks, writer-count saturation, nil receivers and original panics. The separate private-copy arithmetic test passed with `GOTOOLCHAIN=go1.26.6 go test -count=1 -timeout=10m -gcflags=all=-d=checkptr=2 ./iast/propagation -run TestReviewBufferViewBackingWithInteriorSlice -v`.

## Not covered / open questions
