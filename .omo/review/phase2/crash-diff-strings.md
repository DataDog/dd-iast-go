# crash-diff-strings: woven differential fuzzing of strings/fmt/strconv/net/url wrappers
Verdict: No behavior divergence found. Across a 15-minute woven fuzz run (792,544 execs, about 55 ops plus a chain of up to 24 per exec) and 80,000 PRNG iterations on go1.26.6 and go1.27.0, every woven `strings`/`fmt`/`strconv`/`net/url`/`strings.Builder`/concat/slice/`string([]byte)` call returned exactly what the unwoven function-value and reflection calls returned: same results, errors, panics, and callback/`String()` invocation counts. No crash and no cross-request or stale taint was observed. The only provenance defect is the known fmt coarse over-taint (F1, already reported by other nodes, reproduced here independently).
Scope covered: `iast/propagation/{strings.go,coarse.go,operators.go,writer.go (Builder part)}`, `iast/propagation/orchestrion.yml` (string/fmt/strconv/url/Builder/operator aspects), `internal/taint/propagation/{string_exact.go,string_coarse.go,propagation.go (string paths)}`. Run: a woven harness package `iast/internal/crashdiff` in the private copy (root module, so Orchestrion weaves it), `go tool orchestrion go test` with `GOTOOLCHAIN=go1.26.6`, plus go1.27.0 with `GOEXPERIMENT=nojsonv2`.

## Method (summary; details in evidence README)
- `Impl` table with ~65 entries. `Woven` uses direct calls and operators. `Native` uses function values and method expressions. `Reflect` wraps every `Native` entry in `reflect.MakeFunc` and calls it with `Call`/`CallSlice`. `TestWeavingAsymmetry` proves that Woven propagates taint and that Native and Reflect do not. The check runs Native first, because a woven window derivation keys the same (ptr,len), which would taint a later identical native window.
- Each case opens 1-2 real request scopes. It taints a/b/c and a `[]byte` with per-iteration unique source names, and optionally reuses the same tainted value twice. It also feeds woven outputs from earlier, finished requests back in as a "stale" input `d`. Every op runs on all three impls and the outcomes must be `reflect.DeepEqual`. Slicing ops compare only whether a panic occurred, because the reference cannot reproduce the runtime message.
- Taint oracle on every woven output: ranges must be non-empty and in bounds; the source must be one tainted in this iteration, with an identical source value; and for exact ops, every tainted byte must occur in the source value. A chain of up to 24 ops feeds woven outputs forward. A window output that aliases a tainted input but is untainted is recorded and replayed in a fresh request.

## Findings
### crash-diff-strings-F1: fmt coarse propagation taints output bytes that do not come from the tainted argument (independent confirmation of prop-string-coarse-F1/F2, hooks-yml-fmt-strconv-url-F1/F4, prop-semantics-parity-F2)
- Severity: High
- Category: false-positive
- Location: internal/taint/propagation/string_coarse.go:88-121,206-219 (`CoarseFormatString`/`CoarseFormattedString`, `formatArgumentKey`); iast/propagation/coarse.go:48-61
- Claim: `formatArgumentKey` keys any argument whose reflect kind is String or []byte. `publishCoarseOwners` then taints the whole result, whether or not the argument's bytes were rendered. So when a string-kind argument implements `String()` (fmt calls the method and never renders the underlying value), or when the verb does not render the operand (`%T`, `%.0s`, `%[2]s` skipping it), the output is wholly tainted with the request source. A named-string enum whose `String()` maps attacker input to a fixed safe constant, which is a common sanitising idiom, then feeds a tainted query into a SQL sink. `fmt.Sprint*` is an advertised propagation (README "Propagation coverage").
- Evidence: .omo/review/evidence/crash-diff-strings/harness/extra_test.go (`TestTargetedEdges`), output in .omo/review/evidence/crash-diff-strings/targeted.log. Command: `GOTOOLCHAIN=go1.26.6 go tool orchestrion go test -v -run TestTargetedEdges ./iast/internal/crashdiff`. Captured: `Sprint(Stringer named string)  result="constant-red" tainted=true ranges=1`; `Sprintf(%[2]s) result="clean-literal" tainted=true ranges=1`; `Sprintf(%T) result="type=string" tainted=true`; `Sprintf(%.0s) result="xy" tainted=true`. The control `Sprintf(%d, len)` gives `result="14" tainted=false`. The same result appears on go1.27.0 (random-go1.27.0-nojsonv2.log).
- Fix: in `formatArgumentKey`, skip arguments that implement `fmt.Formatter`, `fmt.Stringer`, or `error`, since fmt renders those via methods. When feasible, taint only if the output contains the argument bytes (for example, a bounded `strings.Contains(result, arg)` for small inputs), or parse the format for verbs and argument indexes that do not render.

### crash-diff-strings-F2: tainted `strings.Join` of a single element with a non-empty separator returns a fresh clone where native returns the element (duplicate of hooks-fidelity-strings-F2)
- Severity: Info
- Category: perf
- Location: internal/taint/propagation/string_exact.go:25-46,69
- Claim: the alias fast path runs only when `separator == ""`. With one element and a non-empty separator, `strings.Join` returns `elems[0]` itself, but the tainted path clones it (one allocation plus a new root charge). The content is identical, so this is not a behavior change for immutable strings. The random campaign shows the effect as `JoinSplit aliasMismatch=11299`.
- Evidence: targeted.log `Join([v], ","): woven alias=false native alias=true tainted=true`; random-go1.26.6.log.
- Fix: in `JoinString`, handle `len(elements)==1` as an alias (`StringWindow(elements[0], result)`) regardless of the separator.

### crash-diff-strings-F3: window derivation drops under sustained per-root window load (bounded, not a wrapper-logic bug)
- Severity: Info
- Category: provenance
- Location: internal/taint/propagation/propagation.go:217-256 (`StringWindows`), internal/taint/store/limits.go:17 (`MaxValuesPerRoot = 256`)
- Claim: in the random campaign (50,000 iterations, go1.26.6), about 3,000 window outputs from about 2.2M window-op calls aliased a tainted input but were untainted. Examples: Split 255, FieldsFunc 980, Fields 360. The replay test re-ran the first 200 recorded misses, each in a fresh request with only `a` tainted, and none of them missed again. That fits a documented per-root/per-request capacity limit (hundreds of windows are derived per root per iteration), not a derivation-logic bug. I did not prove which bound was hit.
- Evidence: random-go1.26.6.log (`window misses recorded=200, still missing in isolation=0`, per-op `windowMiss=` counters); random-go1.27.0-nojsonv2.log (same result).
- Fix: none required. Consider a telemetry counter for per-root value-cap drops so the false-negative rate is observable.

## Checked and found correct
- Output parity. The following matched Native and Reflect exactly: every string and []string result, every bool/int result, error type and text, panic values, and the number of predicate/mapping/`String()` invocations (each argument is evaluated and each callback invoked exactly once). This covers: `Clone`, `Cut*`, `Split*` including `SplitN`/`SplitAfterN` with negative, zero, and positive counts, `SplitSeq`/`SplitAfterSeq`/`Lines`/`FieldsSeq`/`FieldsFuncSeq` including early `break` and re-iteration, `Fields*`, `Join` (0, 1, many, and 17+ elements), `Repeat` (negative count panic, overflow panic at `MaxInt`, 0, and 1), `Replace*` with an empty `old` and more than 32 matches, `Replacer.Replace`, all `Trim*`, case conversions including length-changing Unicode, `Map` with deletion and invalid runes, `ToValidUTF8`, `Sprint`/`Sprintf`/`Sprintln` (nil, typed-nil Stringer, panicking Stringer, `[]byte`, named `[]byte`, a struct, a pointer, fuzzed format strings, 17 arguments), URL escape/unescape including `%zz` errors, and `strconv` quote/unquote. Evidence: fuzz.log `PASS ... 901.444s`, 792,544 execs, 0 failures.
- `strings.Builder` sequences (Write, WriteString, WriteByte, WriteRune, Grow with negative-count panic, Reset, String, and the copied-by-value panic) returned identical Len, Cap, and String values and identical panics.
- Concat for 2, 3, 16, and 17 operands (17+ stays untainted as documented), string slicing (panic presence and content), and `string([]byte)` including three-index/cap bounds all matched.
- No taint crossed requests. `CloneStale taintedOut=0` held across all runs, and the oracle never saw a source outside the current iteration, even with GC every 512 iterations and a stale-value feedback loop. All ranges were within bounds, and exact ops only ever tainted bytes present in the source value.
- Go 1.27 stdlib behavior (with `GOEXPERIMENT=nojsonv2`): same parity, 30,000 iterations, PASS.
- Peak RSS of the woven fuzz build and run was 151 MB, and 112-321 MB for the other runs, so the 4 GB threshold was never reached. The first fuzz run died at 26 GB RSS. That was a harness bug: chained `JoinMany` grew the value exponentially. The same crasher input passes once the chain is capped at 4 KiB (see fuzz-run1-harness-oom.log and harness-testdata/). It was not an IAST issue: the growth is in the native result sizes, and IAST roots are capped at 64 KiB.

## Not covered / open questions
- A plain go1.27.0 woven build fails in `encoding/json` advice (`dec.r undefined`). I observed it again here (random-go1.27.0-buildfail.log); it is already reported as base-test-127-F1 / hooks-compile-matrix, so it is not counted in this node's findings.
- `bytes.Buffer` is excluded. Its stdlib method bodies are woven (the invalidate aspects), so a function value does not give an unwoven reference. `bytes.*` functions are only exercised indirectly, via `[]byte` sources.
- Concurrency is not covered. The harness is single-goroutine per fuzz worker, and multi-goroutine and race behavior belong to other nodes.
- Compile-shape variants are not covered: named string types, generics, method values, and non-addressable receivers for the `&X` value templates. This harness only exercises runtime parity.
