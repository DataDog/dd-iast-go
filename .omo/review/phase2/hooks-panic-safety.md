# hooks-panic-safety: panic containment and host panic identity
Verdict: Conditional host-safety failure: fault-injected IAST panics escape three woven entry paths, including replacement of an already-unwinding host panic; the tested native panics retain their type and value when IAST does not itself panic.
Scope covered: All advice IDs in `iast/**/orchestrion.yml`, `internal/spans/orchestrion.yml`; non-test hook implementations in `iast/{propagation,net/http,net/url,io,bufio,encoding/json,database/sql,os/exec,crypto/{hash,cipher}}`; `internal/taint/{http,io,url,json,writer,sql,command,scope,operator}bridge`, `internal/taint/request/{scope,owner,http,lazy,reader}`, `internal/taint/propagation/writer.go`, `internal/spans/{orchestrion,owner}.go`, and `taint/taint.go`. Fault-injection and native-panic controls ran against Go 1.26.6 with Orchestrion in an isolated copy of HEAD `2e23b46`.

## Findings

### hooks-panic-safety-F1: Reader advice leaks an internal panic into host code
- Severity: Critical
- Category: crash
- Location: internal/taint/iobridge/bridge.go:30-42
- Claim: The `io.LimitReader`/`TeeReader`/`MultiReader`/`ReadAll`, `bufio.NewReaderSize`, and `net/http.MaxBytesReader` advice call `iobridge.Propagate` or `ReadAll` without a panic boundary. A panic in IAST's registered reader-ownership or source-publication callback propagates through an otherwise valid customer `io.LimitReader` call. This is **conditional fault-injection evidence**, not a discovered input that naturally panics in `request.PropagateReader`: the violation is lack of containment when internal IAST code panics. The same structural exposure exists in HTTP Begin/Eager/lazy handlers, URL Query, root propagation wrappers and operators, crypto reporters, scope/span advice, and parts of the JSON bridge; do not recover across the original host operation or its caller-supplied functions.
- Evidence: `.omo/review/evidence/hooks-panic-safety/io_reader_repro_test.go` (copy to `iast/io/zz_review_panic_test.go`); `.omo/review/evidence/hooks-panic-safety/woven-io-and-propagation.out.txt`; from the private copy run `GOTOOLCHAIN=go1.26.6 go tool orchestrion go test -timeout 10m -count=1 -run TestReview_InternalReaderCallbackCannotPanicHost ./iast/io -v`. Captured line: `IAST-only panic escaped io.LimitReader: type=*struct { origin string } ... identical=true`.
- Fix: Isolate each IAST-only callback/postprocessing invocation behind a narrow recovering helper at the advice boundary. Keep the original stdlib operation and application callbacks outside that helper so their panic values pass unchanged. Make scope acquisition/teardown transactional if the protected code owns a permit.

### hooks-panic-safety-F2: Native Buffer invalidation can abort the original write
- Severity: Critical
- Category: behavior-change
- Location: internal/taint/writerbridge/bridge.go:75-95
- Claim: The `bytes.Buffer.invalidate-backing`, `invalidate-header`, and `invalidate-exposure` prepend advice calls `writerbridge.Invalidate` **before** executing the native method (`iast/propagation/orchestrion.yml:1553-1680`). `invalidateSlow` invokes the registered IAST callback without recovery. With tracked writer state, a fault in IAST invalidation becomes the host's panic before `bytes.Buffer.WriteString` can write, instead of dropping only taint metadata. This is fault injection of the IAST callback, not evidence that ordinary input currently triggers its panic.
- Evidence: `.omo/review/evidence/hooks-panic-safety/propagation_repro_test.go` (copy to `iast/propagation/zz_review_panic_test.go`); `.omo/review/evidence/hooks-panic-safety/woven-writer-invalidation.out.txt`; `GOTOOLCHAIN=go1.26.6 go tool orchestrion go test -timeout 10m -count=1 -run TestReview_InternalBufferInvalidation ./iast/propagation -v`. Captured line: `IAST-only panic escaped bytes.Buffer.WriteString: type=*struct { origin string } ... identical=true`.
- Fix: Recover around the IAST invalidation callback inside `invalidateSlow`, not around the native Buffer method. On failure, invalidate/dirty the tracked writer state conservatively and clear any expectation marker, then allow the host write to run.

### hooks-panic-safety-F3: Deferred HTTP advice replaces the host's original panic
- Severity: Critical
- Category: behavior-change
- Location: iast/net/http/orchestrion.yml:131-158
- Claim: `Request.ParseForm` installs a deferred `httpbridge.Form` call, including when the native body reader is already unwinding from a panic. An IAST-only callback panic in that defer **replaces** the original host panic (both value and origin); the same ordering applies to deferred `ParseMultipartForm`, `FormValue`, `PostFormValue`, `PathValue`, `Cookie[s]`, `CookiesNamed`, URL `Query`, I/O and JSON advice. The observed fault was deliberately injected; the test separately proves the unmodified reader's host panic survives without that fault.
- Evidence: `.omo/review/evidence/hooks-panic-safety/http_defer_repro_test.go` (copy to `iast/net/http/zz_review_panic_test.go`); `.omo/review/evidence/hooks-panic-safety/woven-http-deferred.out.txt`; `GOTOOLCHAIN=go1.26.6 go tool orchestrion go test -timeout 10m -count=1 -run TestReview_DeferredSource ./iast/net/http -v`. Captured line: `host panic replaced: ... value=&{IAST Form}; internal fault identical=true`, whereas the baseline recovered the exact `hostFault` pointer.
- Fix: Place the deferred IAST-only callback in its own recovering helper so that a host panic already in flight is never replaced. Preserve existing native defers and do not catch/reissue the host panic.

## Checked and found correct

- **Advice inventory without recover, and potential work below each entry:** `iast/propagation/orchestrion.yml:12-404` (15 concat arities, byte conversion, both slice classes) runs the native expression first, then unshielded `internal/taint/propagation` range/window publication; invalid range math, store synchronization or unexpected panics there escape. `:405-1056` (`strings`, `bytes`, `fmt`, `net/url`, `strconv` replacements) runs the native call first, then unshielded taint transformations; the original panic remains untouched when it occurs before propagation, but a later internal panic escapes. User-provided `Map`, `FieldsFunc`, formatting and `Replacer` functions can also panic **as host behavior** and must never be swallowed. `:1057-1552` (Builder/Buffer pointer/value writer and Replacer advice) similarly runs unshielded writer views, range updates and root publication around the native call; Builder copy-check and Buffer bounds panics currently pass through. `:1553-1680` (native Buffer backing/header/exposure) invokes the unshielded pre-method callback (F2).
- `iast/net/http/orchestrion.yml:16-355`: both server and application-handler Begin/Eager/Finish, tracer span binding, MaxBytesReader propagation and all eight lazy form/path/cookie method advices are unshielded. Below them are request sampling/permit acquisition, header and map/source cloning, reader/URL object bindings, span binding and scope finish; `Finish` is installed **before** Eager, but an IAST Begin fault before its defer is installed has no local cleanup. `iast/net/url/orchestrion.yml:13-29`, `iast/io/orchestrion.yml:13-85` and `iast/bufio/orchestrion.yml:16-33` run unshielded owner binding, clone/adopt and map management on return or panic.
- `iast/encoding/json/orchestrion.yml:12-123`: bootstrap is registration only; Bind, Unbind, Quoted and Document/Literal bridge state operations have no whole-entry shield. `jsonbridge.documentSlow` and `literalSlow` recover **callback** panics (`internal/taint/jsonbridge/bridge.go:183-190,241`), and matching `defer Unbind` releases admitted decoder slots during native JSON panics; bridge pointer/state bookkeeping outside those helpers remains unshielded. `iast/database/sql/orchestrion.yml:16-117` and `iast/os/exec/orchestrion.yml:15-78` report through recovering `sqlbridge.Report` and `commandbridge.Report` (`:52-62`, `:43-53` respectively); command advice invokes `os.StartProcess` before reporting. Their registration and declaration advice does not execute request-specific work.
- `iast/crypto/hash/orchestrion.yml:12-136` and `iast/crypto/cipher/orchestrion.yml:12-199` prepend unshielded weak-algorithm reporting (stack capture, dedup, span/event attachment) before the native constructor/hash method. `internal/spans/orchestrion.yml:14-30` calls unshielded `spans.Finished` during `tracer.Span.Finish` (`internal/spans/orchestrion.go:27-60`), including payload encoding and tag submission; its annotation mutex has a deferred unlock, though a panic before `ann.releaseSourceIdentities()` would skip source-charge release. No ordinary-input reproducer for either path was found.
- Woven `TestReview_NativePanicsPreserveIdentity` compared native/wrapped panic **dynamic types and deep values** for `strings.Repeat(-1)`, `bytes.Repeat(-1)`, Builder value-copy check, Buffer `Truncate(-1)`, string out-of-range slice and byte out-of-range slice; all passed. `TestReview_BufferTruncatePanicLeavesTaintAndExpectation` confirmed the tracked Buffer retained taint after invalid truncate and a later write. Existing woven `TestBufferOriginalPanics` passed for Buffer `Peek`, `Truncate`, `Grow`, nil `Grow`/`Write`; `TestDirectNestedAndPanicLifecycle` proved exact host panic propagation and reuse of the one-permit HTTP scope after unwinding. Captured output: `.omo/review/evidence/hooks-panic-safety/woven-native-and-cleanup.out.txt`.

## Not covered / open questions

- Fault injection establishes the missing boundary and host-visible failure; it does **not** establish a naturally reachable internal panic for each grouped callback or a naturally triggered unreleased permit/span source charge.
- JSON, SQL/command and weak-crypto advice were traced statically; no fault-injected end-to-end panic/cleanup fixture was run for their distinct tracer/decoder environments. The six native panic controls compare dynamic type and deep value, not pointer identity for native runtime panic errors; the HTTP test compares its custom panic by pointer identity.
