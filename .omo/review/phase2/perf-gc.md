# perf-gc: GC overhead, weak references, and taint-owner retention
Verdict: No Critical or High GC-retention defect was observed; weak-pointer operations are allocation-free in isolation, all taint-store anchors are bounded and synchronously released at owner finish, and one bounded deferred weak-key cleanup behavior is recorded as Info.
Scope covered: `internal/spans/{annotation.go,owner.go,orchestrion.go,vulnerability.go,tainted.go,orchestrion.yml}`; `internal/taint/store/{store.go,owner.go,root.go,binding.go,writer.go,limits.go}`; request lifecycle/source reset; `benchmarks/overhead/overhead_test.go`.

## Findings
### perf-gc-F1: Dead weak-key annotations await a later trim
- Severity: Info
- Category: memory-bound
- Location: internal/spans/annotation.go:223-245
- Claim: A `weak.Pointer[*tracer.Span]` key becoming nil does not itself release the map value. Its `*Annotation` (including up to 256 KiB of source identities) is deleted only by `trimStore` on a later annotation/bind attempt once the map reaches its trim threshold. Normal woven `Span.Finish` removes it synchronously, so this is a bounded abnormal-lifecycle retention, not an unbounded leak.
- Evidence: static reasoning only (NEEDS-REPRO). `store` is an `xsync.Map[weak.Pointer[*tracer.Span], *Annotation]`; only `DeleteMatching(releaseDeadAnnotation)` calls `key.Value()` and releases source identities. `trimStore` is called from `AnnotationFor` and the new-entry path in `BindScope`, while `internal/spans/orchestrion.yml:13-29` normally invokes `Finished` before every non-nil tracer span finish. Admission is capped by `config.MaxConcurrentRequests`; event-source bytes are independently capped at 2 MiB process-wide.
- Fix: No change required for the normal lifecycle. If strict reclamation after an application forgets `Span.Finish` becomes a product requirement, add a bounded existing lifecycle sweep rather than a finalizer or per-object cleanup registration.

## Checked and found correct
- The audited runtime contains seven `weak.Make` sites: four annotation-map lookup/create paths (`internal/spans/annotation.go:92,110,134,190`), span completion (`internal/spans/orchestrion.go:28`), owner-to-root binding (`internal/spans/owner.go:46`), and orphan annotation creation (`internal/spans/vulnerability.go:29`). There are four relevant `weak.Pointer.Value` calls: one dead-key trim and three owner-binding liveness checks. `internal/taint/store` has no weak pointer, `runtime.AddCleanup`, or `runtime.SetFinalizer` use.
- A sampled request root that binds a span normally creates two weak pointers at bind time (annotation-map key and owner-to-root binding) and one at root-span completion. Orphan reporting creates one annotation key and one completion lookup. Extra `weak.Make` calls are lookup keys, not retained objects.
- `weak.Make` plus `Value` allocates zero objects in a 1,000-run `testing.AllocsPerRun` probe. The reproducer and pass result are in `.omo/review/evidence/perf-gc/weak_pointer_probe_test.go` and `validation.txt`.
- The woven 100,000-iteration weak-hash loop allocates 128 B / 4 allocs per iteration versus the control's 0 B / 0 allocs, and its GC trace repeatedly falls back to a 1 MB live heap. The allocation is report/span-path work; the zero-allocation weak-pointer probe prevents attributing it to `weak.Make`/`Value`. Captured commands and trace are in `.omo/review/evidence/perf-gc/gctrace-weak-hash-no-active.txt`.
- Strong taint roots are exactly `rootRecord.stringAnchor` / `bytesAnchor`; `Owner.Finish` clears every root and its ranges, resets bindings, and releases writer state before subtracting charges (`internal/taint/store/owner.go:155-215`). Tests confirm root charge/value release, reader binding release, and bounded substring retention (`validation.txt`).
- Managed roots are bounded at 2 MiB per owner and 8 MiB process-wide; typed object bindings are capped at 256 per owner (eight readers), writers at eight per owner, and source records at 256 per analysis. Bindings and writer object anchors may retain reachable application graphs outside the byte charge, but their reference counts are bounded and `Analysis.Finish` resets sources before `Owner.Finish` clears all owner anchors (`internal/taint/request/owner.go:257-273`; `internal/taint/store/{binding.go,writer.go,limits.go}`).
- The woven span finish hook runs before every non-nil `tracer.Span.Finish` and calls `LoadAndDelete(weak.Make(span))`. This is one allocation-free map probe per finished span, including spans with no IAST annotation; it guarantees ordinary completion releases annotations without waiting for GC.
- `go tool orchestrion go test ./internal/spans -run '^TestWeakCallsPreserveHTTPDecision$'` passed, confirming woven weak-sink reporting preserves both sampled and rejected HTTP decisions.

## Not covered / open questions
- The fixed 64-owner store has pointer-bearing root/binding tables sized for maximum capacity even when the configured concurrent-request limit is lower. This audit did not measure GC scan bytes or GC CPU under saturated owners versus the default two-owner setting; no severity is assigned without that controlled measurement.
- The Info observation requires a harness that deliberately omits span finish while ensuring the tracer releases its span, then demonstrates the retained annotation until the next trim. It is outside the normal woven lifecycle.
- The active-span trace was intentionally not used as evidence because its output was too large for reliable capture; the recorded no-active-span loop is the bounded, fully captured comparison.
