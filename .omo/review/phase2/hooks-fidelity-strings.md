# hooks-fidelity-strings: Differential fidelity of strings/fmt/strconv/url/operator wrappers vs uninstrumented Go
Verdict: No wrapper returned a different result, error, panic, or callback side effect than the stdlib or native operation across about 530k randomized and table-driven differential cases in 6 taint modes on go1.26.6 and go1.27.0. The one observed divergence is a slice-bounds panic *message*. It happens only where gc's own native message reports the wrong index for a constant-foldable sub-word index, and in those cases the wrapper's message is the correct one. No Critical or High findings.
Scope covered: `iast/propagation/strings.go` (all 39 wrappers), `coarse.go` (all 20 wrappers), `operators.go` (Concat2..16, BytesToString, all 10 slice wrappers), `orchestrion.yml` (the aspect-to-wrapper mapping for these functions); the internal call targets they reach: `internal/taint/propagation/{propagation.go,string_exact.go,string_coarse.go,conversion.go,operator_concat.go}`. The tests were run in a private copy at HEAD 2e23b46 with `GOTOOLCHAIN=go1.26.6` and `go1.27.0`.

## Method (harness)
`evidence/hooks-fidelity-strings/iast__propagation__zz_fidelity_diff_test.go` is a `propagation_test` file. It calls each wrapper directly and compares it with the stdlib or native operation on the same inputs.
- **Modes** (every case runs in all 6): `inactive` (no scope), `active-clean` (live owner, untainted inputs), `tainted` (each input from `taint.TaintString`), `tainted-window` (each input is a derived interior window of a larger tainted root), `stale` (tainted by an owner that has finished), and `other-owner` (tainted by owner A after it finished, with owner B active). Each case also runs the stdlib again on the *same* (tainted) string objects.
- **Compared**: every return value with `reflect.DeepEqual`; the nil/len/cap of `[]string`/`[]byte` headers; errors by type, sentinel identity (`errors.Is`/`==`) and text; panics recovered by `%T` and `fmt.Sprint`; for byte slices, the `SliceData` pointer (the alias must be identical); the callback call sequences of predicates, mappings, `Stringer`, `Formatter` and `GoString`; whether input slices (`Join` elements, `fmt` args) were mutated; and for sequences, a full pass, an early break, and a second pass.
- **Inputs**: empty strings, invalid UTF-8 (`\xff`, lone `\xc3`, surrogate `\xed\xa0\x80`), NUL, length-changing case runes (`İ`, `ß`, `ǅ`, `ﬀ`), `%`-escapes (valid and invalid), quoted and unquoted text, strings over 64 KiB (the MaxRootBytes boundary), and strings with more than 32 windows. Counts include `MinInt`, -100, -1, 0, 1, 31/32/33, `1<<20`, `MaxInt/2` and `MaxInt`. `Repeat` counts are clamped only to avoid multi-TB allocations; the overflow-panic path is kept. Variadic inputs cross the 15/16/17 inspection limits.
- **Panicking callbacks**: the predicate or mapping panics on `'X'`, a `Stringer` panics, and there are nil predicates, nil mappings and a nil `*strings.Replacer`.
- **fmt**: 26 formats (`%!`, `%[5]v`, `%*d`, `%.*s`, huge widths, invalid-UTF-8 formats, and the format string itself tainted) with 0-19 args. Args are mixed: string, `[]byte`, named string, `[]byte` and `[]myByte`, Stringer, panicking Stringer, nil-receiver Stringer, error, Formatter, GoStringer, nil, int, `[]string`, `[2]string`, `reflect.Value`, and nil `[]byte`.

Results (captured logs in the evidence dir):
- `run1-strings-go1.26.6-partial.log`: 42 ops x 6 modes, 422,352 cases, PASS. The log is cut off after this test because the host disconnected during the next one.
- `diff-go1.26.6-10k.txt` (earlier harness revision `..._diff_test_v1.go`, 10k iterations per op and mode with taint-hit stats; for example `tainted/SplitSeq taintedStringOutputs=7737`): `TOTAL divergences=0`. The operators test in the same run reports `divergences=0` with 93,899 tainted inputs.
- `run4-fmt-go1.26.6.log`: 18,000 fmt cases, PASS.
- `run2-...log`: Concat (18k), Slicing (24k iterations x 23 pairs), NilPanics: PASS. That run's fmt failures came from the harness itself: counters printed per-call heap addresses. They were fixed before `run4`.
- `run5-all-go1.27.0-short.log`: the whole harness in `-short` mode on go1.27.0 (82,152 string cases and 5,400 fmt cases), PASS.
- Woven check: `cmd__fidelitydiff__main.go` was built with plain `go build` and with `go tool orchestrion go build`, then run inactive and `ACTIVE=1`. Its 39 scenarios cover concat operands mutated in place, evaluation order, panic order, slicing order, `Replace` argument order, `Repeat` panics, nil `Replacer`, Stringer counts, `Lines` panic in the loop body, `ToUpper` of special runes, and more. All four outputs are identical except `slice-oob-uint8` (see F1).

## Findings
### hooks-fidelity-strings-F1: Slice panic text differs from native when gc constant-folds a sub-word out-of-range index (native message is the wrong one)
- Severity: Low
- Category: behavior-change
- Location: iast/propagation/operators.go:207-305 (StringSlice*/BytesSlice*), woven via iast/propagation/orchestrion.yml:343-403
- Claim: When the compiler can prove a sub-word index value (`var i uint8 = 200; s[:i]`, and likewise `uint16` and `int8`), native gc code panics with a `runtime.boundsError` that reports the wrong index: `[:0] with length 3`, `[0:3]`. The generic wrapper receives the index as a parameter and reports the real index: `[:200] with length 3`, `[-3:]`. A woven binary therefore recovers a `boundsError` whose `Error()` text differs from the unwoven binary. The panic still happens at the same point with the same type, so control flow is unchanged. When the index is not constant-folded, the messages are identical for every width and signedness (`slicepanic` output, and the 24k-iteration slicing differential with int/int8/uint8/int64/uint64/uintptr/mixed index types). By the node's literal rule ("any divergence") this is a divergence. It is rated Low because only the text of a panic from code that always panics changes, and the change corrects a gc reporting error. Treat this as a known difference, not as a wrapper defect.
- Evidence: `evidence/hooks-fidelity-strings/cmd__slicepanic2__main.go`; `GOTOOLCHAIN=go1.26.6 go run ./cmd/slicepanic2` (the same on go1.27.0) prints `DIFF string[:uint8 const] native="runtime error: slice bounds out of range [:0] with length 3" wrapper="runtime error: slice bounds out of range [:200] with length 3"` (5/5 DIFF). The non-constant control, `cmd__slicepanic__main.go`, prints 12/12 SAME. Woven confirmation: `fidelitydiff-plain-*.txt` has `slice-oob-uint8 ... [:0] with length 3` and `fidelitydiff-woven-*.txt` has `[:200] with length 3`. Captured in `slicepanic-output.txt`.
- Fix: None needed in dd-iast-go. Optionally document the difference, and report the wrong native index to the Go project, since the native message is incorrect.

### hooks-fidelity-strings-F2: Tainted `strings.Join` of one element returns a fresh clone where the stdlib returns the element itself
- Severity: Info
- Category: behavior-change
- Location: internal/taint/propagation/string_exact.go:21-48,68-69 (via iast/propagation/strings.go:126-130)
- Claim: `strings.Join([]string{s}, sep)` returns `s` (same backing). The fast alias path in `JoinString` runs only when `separator == ""`, so with a non-empty separator and a tainted `s`, `joinStringHit` clones. The content is equal, so the difference is visible only through `unsafe.StringData`, and it costs one extra `len(s)` allocation per call while tainted. The same clone-instead-of-alias pattern is the documented "one exact-length clone" design for the coarse and exact paths. No other alias case differed: `Replace n=0`, unchanged `ToLower`, identity `Map`, valid `ToValidUTF8`, `Repeat 1`, `""+s`, a Replacer with no match, and a single-string `Sprint` all keep identity in every mode.
- Evidence: `run5-all-go1.27.0-short.log` and `run2-...log`: `ALIAS-DIFF [tainted] Join one equal=true stdAliasesInput=true wrapAliasesInput=false` (the same in `tainted-window`), from `TestFidelityAliasIdentity`.
- Fix: Optional. For `len(elements)==1`, route to `StringWindow(elements[0], result)` whenever `stringAlias(elements[0], result)`, whatever the separator.

### hooks-fidelity-strings-F3: Inactive `BytesToString` heap-allocates where native `string(b)` stays on the stack (already reported elsewhere; the fix probe clarifies the right fix)
- Severity: Info
- Category: perf
- Location: iast/propagation/operators.go:198-204
- Claim: This is the same issue as hooks-yml-operators-F4 and prop-concat-conv-json-F1 and is not re-rated here. The probe adds one thing: evaluating `string(value)` *inside* the `!HasValues()` branch restores 0 allocs for BytesToString. Applying the same restructuring to `Concat2` makes it *worse* (0 to 1 alloc), because `a+b` is then materialized twice in the function. The fix therefore belongs in BytesToString only; Concat2 should keep its shape.
- Evidence: `iast__propagation__zz_fidelity_alloc_test.go` gives `ALLOCS native string(b) 0.0` / `BytesToString(b) 1.0` / `native a+b 0.0` / `Concat2(a,b) 0.0`. `iast__propagation__zz_fidelity_allocfix_test.go` gives `fixed BytesToString 0.0` / `fixed Concat2 1.0` (go1.26.6 and go1.27.0, `run5` log).
- Fix: `if !operatorbridge.HasValues() { return string(value) }` before the conversion in BytesToString only.

## Checked and found correct
- Every wrapper evaluates the stdlib call exactly once, before any taint work, and returns its values unmodified in content. Stdlib panics (negative or overflowing `Repeat`, nil `Replacer`, nil predicate, nil mapping, nil `FieldsFuncSeq` predicate, panicking callbacks) surface with an identical type and value, because no internal code runs before the panic. `TestFidelityNilPanics` passes in all modes.
- Predicate, mapping, Stringer, Formatter and GoStringer invocation sequences are identical. `CoarseFormatString` and `CoarseFormattedString` use `reflect.Kind` with `String()`/`Bytes()` on the reflect value only (string_coarse.go:206-221), so they never call user methods a second time. Named `[]myByte` args, nil `[]byte`, `reflect.Value` args and >16 args are safe.
- Iterator wrappers (`stringWindowSeq`): early break, re-iteration, a panic in the loop body (woven `lines-panic-body`), and >32 elements all behave like the stdlib.
- Errors from `url.QueryUnescape`, `url.PathUnescape` and `strconv.Unquote` are the same objects (`EscapeError` text, `strconv.ErrSyntax` identity), and the result string on error is `""` as in the stdlib (the CoarseString `len<2` fast return).
- `StringsToValidUTF8` pointer comparison, `Replace` and `ReplaceAll` with `old==""` over invalid UTF-8, and `Replace` with count `MinInt`/`MaxInt`: the result is always the stdlib result. The internal segment mapper only affects provenance and is guarded by `total != len(clone)`.
- Byte-slice wrappers return exactly the native header (same `SliceData`, len, cap, nil-ness) for `[:]`, `[l:]`, `[:h]`, `[l:h]`, `[l:h:m]` and `[:h:m]`, including named `[]byte` types and nil slices. `BytesToString` and `Concat2..16` (plain and named string types) are content-identical in all modes.
- Allocation parity (`TestFidelityAllocations`, inactive and active-clean): no alloc difference for 23 direct-call wrappers, including `SplitSeq`, `Lines`, `FieldsSeq` and `FieldsFuncSeq` in a `for range` loop. That call shape lets the wrapper closure inline, so it does not contradict perf-hotpath-F1, which measured non-inlined use.

## Not covered / open questions
- Taint *provenance* correctness is out of scope (see the prop-* and hooks-yml-* nodes). Tainted modes were checked only for fidelity. The harness confirms taint hits are exercised (`diff-go1.26.6-10k.txt` STAT lines).
- `bytes.*` and writer wrappers belong to hooks-fidelity-bytes and prop-writer.
- Concurrency: no race-mode run of the differential. Wrappers share no mutable state beyond the store, which other nodes cover.
- Orchestrion-side argument evaluation and compile issues (array operands, float constant bounds, method expressions) are covered by hooks-yml-operators and hooks-yml-strings, not re-checked here.
