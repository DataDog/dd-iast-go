# crash-panic-static: Static panic-site enumeration for hook-reachable production code
Verdict: One Critical panic is reachable. Weak-crypto hooks call into IAST through `go:linkname` before `internal/spans` and the dd-trace-go tracer have initialized, so a customer package that hashes with md5 or sha1 during its init crashes the process at startup under the default config. I reproduced it on go1.26.6. Every other index, slice, assertion, map, division, make, and overflow site I enumerated is provably safe or sits behind a verified recover.
Scope covered: I read every non-test, non-generated `.go` file under `taint/`, `internal/` (bridges, request, store, ranges, propagation, evidence, redaction, spans, vulnerability, dedup, stacktrace, model, config, instrumentation, telemetry), and `iast/` (propagation wrappers, sinks, json, bufio, http, crypto). I also read all non-propagation `orchestrion.yml` templates (http, json, io, bufio, url, sql, exec, crypto, spans), `weak.Make` / `getWeakHandle` in the go1.26.6 runtime, and dd-trace-go v2.11.0-rc.1 `globaltracer.go`, `CaptureStackTrace`, and `RecordStackTrace`. I ran two recover-semantics tests (go1.26.6 and go1.27.0) and one woven reproducer build (`/usr/bin/time -l`: 423 MB max RSS, 70 s).

## Findings
### crash-panic-static-F1: Weak-crypto hooks panic during package init: IAST runs before spans/tracer are initialized
- Severity: Critical
- Category: crash
- Location: iast/crypto/hash/orchestrion.yml (the `prepend-statements` `__dd__iast_ReportWeakHash__(nil, crypto.MD5|SHA1|MD4)` in `md5.New`/`md5.Sum`/`sha1.New`/`sha1.Sum`/`md4.New`, reached through `//go:linkname ... iast/crypto/hash.ReportWeakHash`); iast/crypto/cipher/orchestrion.yml (same shape for DES, 3DES, RC4, Blowfish, RC2, PKCS12); internal/vulnerability/report.go:37-52; internal/spans/vulnerability.go:18; internal/spans/annotation.go:29-31,52
- Claim: The crypto aspects inject a direct `go:linkname` call into stdlib function bodies. `links:` adds a link dependency, not an import, so Go's init ordering does not initialize `iast/crypto/hash` and its dependencies (`vulnerability`, `spans`, dd-trace-go `tracer`, `instrumentation`) before code that calls `md5.Sum`/`sha1.New`/`des.NewCipher`. `internal/config` initializes very early (its dependencies are only `regexp` and dd-iast-go internals), and `config.Enabled` defaults to **true** (`config.go:72`). `vulnerability.Report` therefore passes its only gate (`report.go:37`) and runs against uninitialized packages:
  - `tracer.StartSpan` calls `internal.GetGlobalTracer[Tracer]()`. Before the tracer's `init` (`globaltracer.go:10-13`), that is a nil `any`, and the unchecked type assertion panics with `interface conversion: interface {} is nil, not *tracer.Tracer`.
  - If the tracer happens to be initialized but `spans` is not, `nonSampledAnnotation` (annotation.go:29) and `store` (annotation.go:31) are nil, so `ann.Sampled` (report.go:52) and `store.Size()` in `trimStore` dereference nil.
  - The window runs from `internal/config` init to `internal/spans` init. Any package whose path sorts after `github.com/DataDog/dd-iast-go/internal/config` (every lowercase `github.com/<org>`) and whose dependencies finish in that window hits it, for example any package that imports `regexp` and computes a digest in a `var` initializer or `init()`. Transitive third-party dependencies count too. Nothing recovers on this path: it is not behind a bridge `recover`, and the panic kills the process before `main`. `DD_IAST_ENABLED=false` avoids it.
- Evidence: Reproducer at `.omo/review/evidence/crash-panic-static/initorder-repro/`: `hasher/hasher.go` holds `var idPattern = regexp.MustCompile(...)` and `var Seed = md5.Sum(...)`; `main.go` imports it; `orchestrion.tool.go` imports `iast/crypto/hash` plus the tracer. Command: `GOFLAGS='-p=4 -mod=mod' GOTOOLCHAIN=go1.26.6 go tool orchestrion go build -o initorder . && ./initorder`. The full output is in `initorder.out.txt`. Key lines:
  `panic: interface conversion: interface {} is nil, not *tracer.Tracer` ... `tracer.StartSpan` <- `spans.NewOrphanVulnerabilitySpan() vulnerability.go:18` <- `vulnerability.Report report.go:47` <- `hash.ReportWeakHash hash.go:19` <- `crypto/md5.Sum <generated>:2` <- `github.com/zzz/initorder/hasher.init() hasher.go:13`, `EXIT=2`. With `DD_IAST_ENABLED=false` the output is `started ok ... EXIT=0`. `GODEBUG=inittrace=1` shows `init .../internal/config`, then `init .../internal/taint/request`, then the crash. The tracer and spans never initialize.
- Fix: Do not call reporting code through `go:linkname` directly. Route it through a dependency-minimal bridge (an `atomic.Pointer` callback, as `sqlbridge`/`commandbridge` do) that `iast/crypto/{hash,cipher}` registers in their own `init()`. Those packages import `vulnerability`, which imports `spans` and `tracer`, so registration happens only after everything they need has initialized. Until then the call is a no-op. Also wrap the callback in `defer func(){ _ = recover() }()`, like the SQL and command bridges. A minimal alternative: an `atomic.Bool` "ready" flag set at the end of `iast/crypto/hash` and `iast/crypto/cipher` `init()` and checked first in `ReportWeakHash` and `ReportWeakCipher`. Add a woven regression test with an init-time `md5.Sum`.

### crash-panic-static-F2: Only three bridges have a panic boundary; the other hook entry points run unshielded in host goroutines
- Severity: Low
- Category: crash
- Location: internal/taint/httpbridge/bridge.go:69-156; internal/taint/iobridge/bridge.go:30-43; internal/taint/urlbridge/bridge.go:25-31; internal/taint/writerbridge/bridge.go:83-95; internal/taint/scopebridge/bridge.go:25-30; internal/spans/orchestrion.go:27-60 (the `Span.Finish` hook runs for every span in the process); iast/propagation/*.go (operator and writer wrappers); internal/vulnerability/report.go:30-109
- Claim: `recover` exists only in `sqlbridge.Report`, `commandbridge.Report`, `jsonbridge.{documentSlow,literalSlow}`, and `spans.TryCommitTainted`. HTTP, reader, URL, writer, operator, scope-finish, span-finish, and crypto hooks call request, store, propagation, and spans code with no boundary, often from a `defer` inside stdlib functions that may already be unwinding. My enumeration found no reachable panic site in those paths today (see "Checked and found correct"). Crash-safety of the host therefore rests entirely on per-site proofs rather than on a structural guarantee. One future indexing regression would crash customer requests, or all span finishes.
- Evidence: static reasoning only (no reachable trigger found).
- Fix: Add `defer func(){ _ = recover() }()` in the non-inlined slow paths behind the cheap gates: `request.EagerHTTP`/`Manage*`, `PropagateReader`/`ReadAllBytes`, `ManageURLQuery`, `invalidateBuffer`, `spans.Finished`, `vulnerability.Report`, and the propagation `*Hit` functions. Keep the fast gates defer-free.

### crash-panic-static-F3: A recovered sink panic would leak store locks that are unlocked manually rather than deferred
- Severity: Info
- Category: deadlock
- Location: internal/taint/store/lookup.go:114-185; internal/taint/request/lookup.go:143-157; internal/taint/store/binding.go:133-152; internal/taint/store/writer.go:88-100,375-398; internal/taint/store/mutation.go:43-66; internal/taint/store/root.go:371-395
- Claim: The sink bridges `recover`, but the store and request code they call releases `TryLock`/`TryRLock` manually on each path. A panic between lock and unlock would be swallowed with the lock still held. Later `TryLock`s would drop forever (a silent permanent self-disable for that shard or owner slot), and the blocking `Lock()` in `Owner.Finish` / `bindingTable.reset` would deadlock the request goroutine. The code inside these critical sections is provably panic-free today (fixed-array indexes bounded by constants, `ranges` ops that return `Valid=false`), so this is latent.
- Evidence: static reasoning only.
- Fix: Keep the critical sections free of calls that can panic, and document that invariant next to the sink `recover`, or switch these sites to deferred unlocks inside small helper functions.

## Checked and found correct
- **Recover semantics**: a deferred `sqlbridge.Report` running while the host `database/sql` method panics, and a deferred `jsonbridge.Literal` running while `literalStore` panics, recover only the callback's own panic and propagate the host panic unchanged. Tests are `internal/taint/{sqlbridge,jsonbridge}/zz_review_recover_test.go` in the private copy; both pass on go1.26.6 and go1.27.0 (`evidence/crash-panic-static/recover-semantics.out.txt`). `commandbridge.Report` runs after `os.StartProcess` returns, so it cannot mask a host panic either.
- **Type assertions**: the only ones are `ctx.Value(...).(*Scope)` (scope.go:166) and `result.(string)` (jsonbridge:134), both comma-ok. `reflect.Value.Bytes()` (string_coarse.go:216) is guarded by `Elem().Kind()==Uint8 && !IsNil()`, which matches reflect's own precondition, so named byte element types are safe. `value.Addr()`/`SetString` in json.go:39-43 are guarded by `CanAddr`/`CanSet` and shielded.
- **Fixed-array indexes**: `Table.prepare/commit` (count < 256, slot masked 511); `taintHeaders`/`manageMap` (the second loop rechecks `entryCount`/`valueOffset` against the array sizes, so a map changing size between loops cannot overflow); `Manager.Acquire` (index < max <= 64); `directory[ownerIndex]` (Index validated < 64); `copySources`/`deliverEntry` (`CopyTo` <= 64); shard probing `(uint8+probe)%128`; `putWindow`/`insertWindow`/`stale`/`reclaim` (`rootID`/`ownerIdx` checked); overflow blocks (index <= 256, `-1`); `publishRangesLocked`/`prepareRanges` (count <= 64, overflow copy <= 54); `rootFree` (N <= reserved IDs <= 512); binding table (count < 256, `readerCount--` only when it counted a reader); writer tables (count < 8); jsonbridge (64 slots) and writerbridge (128 slots) modular probes; `ownerSpans[index]` (checked < 64); `TryCommitTainted` `eventSourceIndexes`/`redacted`/`stagedModels` (every eventIndex < `len(identities)+len(new)` <= 256); evidence collector (count < 256, sources < 256, index 512 masked).
- **ranges algebra**: every `Set` producer keeps `count <= limit <= 64`, and `CopyTo` uses `copy`. `Canonicalize` fragments stay <= 2n-1 <= 383 (each candidate adds at most 2 boundaries), within the 383-sized arrays, with an explicit precheck. `Repeat` checks `sourceLen==0` before dividing. `appendWindow`/`Before`/`After` use unsigned min/max with clipping (no negative lengths). Invalid inputs return `Valid=false` and never index.
- **String and slice expressions**: `mapReplaceSegments`/`mapReplaceByteSegments` (matches < 32 gives indexes <= 64 in a 65-array; `input[last:]` with `last <= len`); `mapValidUTF8Segments` (precheck `segmentCount+2 > 64`); `jsonbridge.Literal` (`original[offset:end]` with `end <= len`; `clone[offset:offset+len]` with overflow-safe `uintptr` checks); `JSONString` offset via `bytesAlias`; `matchesJoin`, `PartValue`, `truncateRedactedEvidence` (`remaining < len`), `mappedPattern` (`offset+len(value) <= len(sourceValue)`), `scanOracleQuotes`, `dollarQuoteBody`, `joinedFunctionMatches`, `AnalyzeCommand` (`argv[0]` with len >= 1), `truncation.String`.
- **Slicing and conversion operator wrappers** (`iast/propagation/operators.go`) evaluate the host slice first, so out-of-range panics are the host's own. Generic integer bounds (including `uintptr`/`uint64`) keep native bounds-check semantics. Writer wrappers on nil or copied receivers panic inside the same stdlib method class (`String`/`Bytes`/copyCheck) that the native call would hit. `BufferString(nil)` and `BufferGrow(nil)` are special-cased, and `Cancel` is deferred, so expectation slots are released on panic.
- **Division/modulo**: all by non-zero constants, except `Repeat` (guarded) and `Stats` (guarded float). **make**: every computed size is bounded (<= 64 KiB, 256, 513, or map length). **Channels**: none in production code. **Integer overflow**: `uint32` casts are either prechecked (`StringKey`/`BytesKey` <= `MaxUint32`, <= 64 KiB roots) or only feed `ranges` validators and never slice bounds.
- **`weak.Make`** on non-heap pointers does not throw in go1.26.6 (`getWeakHandle` falls back to `immortalWeakHandles` for `isGoPointerWithoutSpan`). **Tracer helpers**: `CaptureStackTrace`/`RecordStackTrace` are nil-safe. **constants**: `name()` panics are reachable only from the test helpers `AllOrigins`/`AllVulnerabilityTypes`; `String()` has a default branch.
- **Templates**: nil receivers and requests are guarded in the http/sql/bufio/cookie templates. The deferred template closures call only the (panic-free) bridge code above.

## Not covered / open questions
- I built and ran F1 only on go1.26.6. Go's init order is specified, so go1.27 should behave the same, but I did not rebuild on it.
- I did not survey which real third-party modules compute md5/sha1 in `init` or `var` initializers (which would make F1 fire with no customer code involved).
- I only skimmed the `iast/propagation/orchestrion.yml` operator templates. Their evaluation-order and panic-order equivalence belongs to the boundary/operator nodes.
- The third-party `go-sqllexer` and `xsync` internals were not audited. sqllexer runs only behind the SQL-sink `recover`; xsync runs unshielded in `spans` (F2).
- Races that could tear a `ranges.Set.count` (which would make `CopyTo` slice out of range) were not examined dynamically. All `Set` copies I read happen under the owning lock.
